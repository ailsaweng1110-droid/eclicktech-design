# 移动端适配（Tailwind，移动优先）

面向「AI 建站」场景：桌面端页面已生成后，用统一规则把它适配到移动端，避免逐页返工、避免各页标准不一致，避免「只把桌面布局等比缩小」。

## 核心原则（必须遵守）

0. **禁止改动网站端（桌面）样式**：本 skill 只做移动端/平板适配，**桌面端（≥1024px）的渲染效果必须与适配前完全一致**。只能新增或修改移动/平板断点（默认 + `md:`）的样式；若原代码是「桌面优先」（基准样式即桌面值），改动基准值时必须同步加 `lg:` 前缀把原桌面值锁定。唯一例外：导航从桌面横向栏改为移动端汉堡菜单（见规则 8）。完成后在 ≥1024px 宽度下对比，桌面必须像素级一致。
1. **移动优先（Mobile-first）**：默认（无前缀）样式 = 移动端，用 `md:`/`lg:` 向上叠加平板/桌面样式。**禁止**先写桌面再单纯缩小。
2. **重排而非缩放**：移动端要改变布局结构（多列变单列、横排变竖排、导航变抽屉），而不是把桌面整体缩小。
3. **全站一致**：公共组件（导航/页脚）与排版（H1/H2/正文字号）在所有页面必须使用同一套标准，不允许一页大一页小。
4. **图片保持原比例**：图片素材等比缩小，禁止改变比例、拉伸或裁切变形。
5. **触控友好**：所有可点击元素触控区 `≥ 44×44px`；hover-only 的交互必须有触摸替代。
6. **不横向溢出**：任何页面在 375px 宽下都不得出现横向滚动条或组件溢出。

## 工作流程

复制并跟踪此清单：

```
移动端适配进度：
- [ ] 步骤 1：读取目标页面，识别布局区块（导航/Hero/多列/图片/表格/表单/页脚）
- [ ] 步骤 2：按 rules.md 逐区块套用统一规则（断点、边距、字号、间距、多列、图片、按钮、导航、顺序）
- [ ] 步骤 3：按 patterns.md 应用「桌面→移动端」转换代码模式
- [ ] 步骤 4：按 checklist.md 逐项自检（对照代码 + 心智清单，属 Pass A）
- [ ] 步骤 5：按 rules.md「溢出与裁切审查」修复拥挤/溢出/交互问题
- [ ] 步骤 6：【强制】Pass B 实测自检并修好再交付（见下；用户未要求也要做）
```

**步骤 1 — 识别区块**：先判断页面由哪些区块组成，逐块处理，保证全站各页用同一套标准。

**步骤 2 — 套用统一规则**：所有数值/断点/尺寸规范见 [rules.md](rules.md)。不要临时发明数值。

**步骤 3 — 应用转换模式**：常见桌面结构 → 移动端结构的 Tailwind 写法见 [patterns.md](patterns.md)。

**步骤 4 — 自检（Pass A）**：用 [checklist.md](checklist.md) 逐项核对。这只是第一遍，**不能**到此就告诉用户「适配完成」。

**步骤 5 — 审查修复**：重点排查溢出、内容拥挤、导航不可用、触控目标过小、图片变形，见 rules.md 第 11 节。

**步骤 6 — Pass B 强制实测自检 + 修复（交付门禁）**

> 现实：第一轮实现往往「看起来做完了」，但 logo 条过大、合成图用错、1440 重叠、死箭头等问题要靠**再检查一轮**才会暴露。用户不应亲自催「你再检查一遍」——**skill 要求你在首次交付前自己跑完 Pass B。**

1. **有 dev server 时必须实测**（Playwright / Puppeteer / 等价工具）：在 **375、768、1440**（至少 375 + 1440）下：
   - 分段截图（按 section 或约一屏高），**阅读**截图而非只保存；
   - 脚本量关键元素实际宽高（logo 卡、主 CTA、图标、`absolute` 旁的标题 left）；
   - 检测页面级横向溢出（`scrollWidth > clientWidth`）。
2. **对照 [checklist.md](checklist.md)「Pass B 高频漏项」**逐条过：合成图、logo 条尺寸、多层 logo、双态切换、轮播箭头、1440 重叠等。
3. **发现问题立刻改代码**，改完对相关断点**再测一轮**（至少复测出问题的宽度），直到 Pass B 无新增问题。
4. **未完成步骤 6 不得宣称适配完成**；回复用户时应默认已含 Pass B。若环境无法开浏览器，须在回复中写明限制，并完成代码级 Pass B（通读关键组件 + checklist 高频漏项），能测的部分仍要测。

完整门禁与脚本见 [rules.md](rules.md) 第 13 节。
## 最常用规则速查

- 容器：`mx-auto w-full max-w-screen-xl px-4 md:px-6 lg:px-8`
- 多列：`grid grid-cols-1 gap-4 md:grid-cols-2 lg:grid-cols-3`
- 横排转竖排：`flex flex-col md:flex-row`
- 正文字号：`text-base`（16px）起，**禁止 < 14px**；全站统一，标题用 `text-2xl md:text-4xl lg:text-5xl`
- 段落间距：`py-12 md:py-16 lg:py-24`（区块垂直间距）
- 按钮：主 CTA `w-full md:w-auto min-h-11`；**行内/次级按钮保持自适应宽度靠左**，别一律全宽（见 rules 7）
- 标签胶囊/badge/自适应按钮在 `flex flex-col` 里会被拉满，须加 `w-fit`/`self-start`（见 rules 7.1）
- 图片：`w-full h-auto`（保持原比例等比缩小）
- 整幅媒体（hero/banner/地图）移动端可**满宽出血**，侧边距只约束文字容器（见 rules 2）
- 「文字烤进图片」的区块：移动端用**无文字图 + HTML 实时标题**，`lg:hidden`/`hidden lg:block` 切换（见 rules 6）
- 内容显隐按断点用 `lg:hidden`/`hidden lg:block`，不要删 DOM；桌面省略的正文手机应补全（见 rules 10）
- 全局图片规则：**禁止裸写 `img { height:auto }`**（Tailwind v4 会击穿 `h-*`/`size-*`）；须放进 `@layer base` 并排除自带尺寸类的图片（见 rules 6.1）
- 图标：方形用 `size-*`；非方形必须同时给宽高，禁止只给一边 + `w-auto`（会撑到 ~300px）；导出图标常「紧裁到字形」别塞满外框（外框占位 + 字形缩小），方向性图标（箭头/chevron）用前核对设计稿 `rotate`（见 rules 6.2）
- **Logo 条 / 跑马灯**：卡片外框 + 内部字形都要按断点缩小，用 `lg:` 锁桌面稿尺寸；禁止手机仍用接近桌面的 `h-24`/`min-w-[232px]`（见 rules 6.3）
- **导出素材认清节点**：整 section 合成图 ≠ 单栏插画；合成图要裁/按插画节点重导，避免左右栏内容重复（见 rules 6.4）
- **多层品牌标**：多片 SVG 叠 logo 时对照截图核叠放顺序与命名，勿按文件名猜测（见 rules 6.5）
- **1920 绝对定位桌面**：`absolute` + 定宽在 1024–1919 会重叠裁字 → 改 `flex`/`grid` 流式，或满稿布局放到 `xl:`（见 rules 5.1）
- **桌面半展开双态**：手机用 tab/分段器且切换要换正文；桌面勿硬加手机 tab（见 rules 10.1）
- **轮播/跑马灯箭头**：可见分页必须能滚动或切页，禁止纯装饰死箭头（见 rules 11）
- 导航：桌面横向 nav 在移动端改汉堡 icon 点击展开
- 公共组件（导航/页脚）：全站复用同一个组件
