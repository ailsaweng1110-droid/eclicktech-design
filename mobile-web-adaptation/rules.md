# 移动端适配规则与数值规范（Tailwind）

所有页面统一使用以下规范，保证站内各页适配标准一致。默认（无前缀）= 手机；`md:` = 平板；`lg:` = 桌面。

## 0. 前置约束：禁止改动网站端（桌面）样式

- 本规范只用于移动端/平板适配，**桌面端（≥1024px）的渲染效果必须与适配前完全一致**。
- 只允许新增/修改「默认（手机）」与「`md:`（平板）」断点的样式；不要改变 `lg:`/`xl:` 断点上原有的桌面表现。
- 若原代码是「桌面优先」（基准无前缀样式即桌面值），当你为移动端修改基准值时，**必须同步给该属性加 `lg:` 前缀把原桌面值显式锁定**，防止移动端改动向上泄漏影响桌面。
  - 例：原 `class="grid-cols-3"`（桌面 3 列）→ 改为 `class="grid-cols-1 md:grid-cols-2 lg:grid-cols-3"`，桌面仍是 3 列。
- 唯一例外：导航栏由桌面横向菜单改为移动端汉堡菜单（见第 8 节），桌面导航样式本身不变。
- 完成后在 ≥1024px 宽度下对比适配前后，桌面必须像素级一致。

## 1. 断点

| 设备 | 宽度 | Tailwind 前缀 | 说明 |
|------|------|--------------|------|
| 手机 | < 768px | 无前缀（默认） | 基准样式，按最窄 375px 设计 |
| 平板 | 768–1023px | `md:` | 通常 2 列 |
| 桌面 | ≥ 1024px | `lg:` | 保留原桌面布局 |
| 大屏 | ≥ 1280px | `xl:` | 仅在需要更宽容器时用 |

测试基准宽度：**375px（iPhone）** 与 **768px（平板）** 必测。

## 2. 页面边距与容器

- 页面主容器统一：`mx-auto w-full max-w-screen-xl px-4 md:px-6 lg:px-8`
- 手机左右边距 **16px（`px-4`）**，平板 24px，桌面 32px。禁止移动端沿用桌面的大留白（如 `px-24`）。
- **与设计稿 gutter 冲突时**：若 Figma 桌面是大留白（如 `px-40` / 160px），**桌面用 `lg:`/`xl:` 锁稿面值**；手机/平板仍用本规范的 `px-4`/`md:px-6`，不要把桌面大留白带到移动端。skill 的 `lg:px-8` 是无稿时的默认，有稿以稿为准并显式锁定。
- 内容最大行宽（正文段落）：`max-w-prose`，避免每行超过 75 字符。
- **侧边距只约束「文字/内容容器」**：Hero、banner、地图、整幅插画等**媒体可以边到边满宽出血**，不要硬套 16px 内边距把它缩进去。做法：标题/文字放在带 `px-4` 的容器里，整图容器不加侧边距（`w-full`，必要时 `max-w-[1920px] mx-auto`）。

## 3. 字号（全站统一，禁止 < 14px）

**关键：H1/H2/H3 及正文的字号必须全站统一——同一层级在每个页面用完全相同的大小，不允许一页大一页小。** 建议在设计系统/全局样式或统一组件中定义，各页复用。

| 用途 | 手机 | 桌面 | Tailwind（全站统一） |
|------|------|------|----------|
| 正文 | 16px | 16–18px | `text-base lg:text-lg` |
| 小字/说明 | 14px | 14px | `text-sm`（下限，勿更小） |
| H3 | 18–20px | 24px | `text-lg md:text-2xl` |
| H2 | 24px | 30–36px | `text-2xl md:text-3xl lg:text-4xl` |
| H1 / Hero | 30–36px | 48–60px | `text-3xl md:text-5xl lg:text-6xl` |

- 同一标签（如所有 H2）在全站使用相同的字号类组合；若某页需要特殊尺寸，应作为设计系统中明确定义的变体，而非随手改数值。
- 行高：正文 `leading-relaxed`，标题 `leading-tight`。
- 大标题优先用 `text-balance`（标题）/ `text-pretty`（正文）避免难看的换行。

## 4. 间距（按层级缩小，不等比缩放）

- 区块（section）垂直间距：`py-12 md:py-16 lg:py-24`
- 元素间距：`gap-4 md:gap-6 lg:gap-8`
- 卡片内边距：`p-4 md:p-6`
- 原则：移动端间距整体收紧，但保持层级清晰；不要把桌面的 `py-32` 直接搬到手机。

## 5. 多列结构

- 网格：`grid grid-cols-1 gap-4 md:grid-cols-2 lg:grid-cols-3`（桌面 4 列则 `lg:grid-cols-4`）。
- 卡片列表在手机可用 2 列（`grid-cols-2`）承载小卡片；信息密集的卡片用单列。
- 横向排布：`flex flex-col md:flex-row`。
- 侧边栏 + 主内容：手机堆叠为单列，侧边栏移到主内容之后或折叠。
- 表格：手机改为「卡片式」堆叠，或 `overflow-x-auto` 横向滚动（并给出滚动提示），禁止让表格撑破视口。

## 5.1 1920 稿面的绝对定位：在 lg（1024–1919）会撞车

> 高频事故：Figma 按 1920 画「左侧 `absolute` 大图 + 右侧定宽列表」。代码用同一套 `absolute` + `max-w-[960px]` + 大 `px-40` 锁桌面后，在 **1440** 等中间宽度内容区不够宽，图文重叠、标题被裁成「…Fraud」「Driven…」。

- **不要**把 1920 满稿的绝对坐标原样当成所有 `lg:`（≥1024）的布局。
- **优先**：桌面也改成 **流式** `flex` / `grid`（图 `shrink-0` + 文 `min-w-0 flex-1`），在 1024–1919 自动让位、不重叠；到 `xl:`/`2xl:` 再接近稿面间距。
- **备选**：仅在 `xl:`（或接近 1920 的断点）启用绝对定位满稿布局；`lg:` 用流式两栏。
- 自检：在 **1440** 与 **1024** 量标题 `getBoundingClientRect().left`，确认不被左侧媒体挡住；全文标题可读、无被裁切。

## 6. 图片与媒体比例

- **保持图片素材原始比例，等比缩小，禁止改变比例、拉伸或裁切变形**。用 `w-full h-auto` 让图片按容器宽度等比缩放。
- 不要为移动端强行套用与原图不同的固定比例容器去裁切主体；确需固定容器时，比例应与素材一致并用 `object-contain` 保证完整显示。
- 响应式图源：`<img srcset sizes>` 或 Next `<Image sizes="(max-width:768px) 100vw, 50vw">`，移动端加载更小尺寸但比例不变。
- 图标/装饰图在手机可隐藏：`hidden md:block`（仅限非关键内容）。
- 背景图：`bg-contain`/`bg-cover bg-center`，优先保证主体完整且比例不变。
- **「文字烤进图片」的区块要特别处理**：桌面常把标题/说明直接烤进大图（hero、banner、地图等）。移动端**直接缩这张图会导致图内文字太小看不清，或与页面上的实时标题重复**。做法：
  - 移动端改用**无文字的纯图素材** + 用 **HTML 实时文本**写标题/说明（可读、可换行、可选中）；
  - 桌面若仍需原带文字大图，用 `lg:hidden` / `hidden lg:block` 切换两套图；
  - 若拿不到无文字素材，至少把实时标题移出图片、避免与图内文字重复。

## 6.1 全局图片规则的正确写法（Tailwind v4 必读）

> 高频事故：为"图片等比缩小"写了一条全局 `img { height: auto }`，结果把整站图片尺寸搞坏——Hero 背景 `size-full` 从铺满塌成一条、图标 `h-12` 被撑到几百像素。表面看像"好几个不同的适配 bug"，实则同一个根因。

- **禁止裸写（unlayered）全局 `img { height: auto }`。** Tailwind v4 的工具类都在 `@layer` 内，而 CSS 级联规定**未分层规则优先级高于任何 `@layer`**；这条全局规则会**击穿**所有 `h-*` / `h-full` / `size-*` 高度工具类，导致设了固定高度/铺满的图片全部失效。
- 正确做法：放进 `@layer base`，并只对"未自带高度类"的图片兜底：

```css
@layer base {
  img { max-width: 100%; }
  /* 只兜底没有显式设高度的图片，避免覆盖 h-*/size-* 工具类 */
  img:not([class*="h-"]):not([class*="size-"]) { height: auto; }
}
```

- 同理，任何"想统一覆盖某元素"的全局标签选择器（`img`/`svg`/`video` 等）都必须写进 `@layer base`，否则会盖过工具类。

## 6.2 图标 / SVG 尺寸

- **方形图标**用 `size-*`（同时锁定宽高，如 `size-6`/`size-12`），最稳。
- **非方形图标必须同时给出宽和高**（如 `h-12 w-[30px]`）。**禁止只给一边 + `w-auto`/`h-auto`**：当浏览器推导不出 SVG 内在比例时，会退回替换元素默认尺寸（约 300×150px），把图标撑成一大块。
- **Figma / 设计工具导出的 SVG 先归一化再用**：这类 SVG 常带 `preserveAspectRatio="none"` 与 `width="100%" height="100%"`，本身没有内在比例，`w-full h-auto` 无法正确等比缩放。处理：删掉 `preserveAspectRatio="none"`，并用其 `viewBox` 补回显式 `width`/`height`。
- 用固定尺寸容器包裹图标时，容器用 `size-*`，内部 SVG 用 `size-full`，可绕开内在比例缺失的问题。
- **导出的图标常「紧裁到字形」，丢了设计稿里的内边距——别按原尺寸塞满容器**：Figma 图标组件通常是「固定外框（如 32px）+ 字形只占中间一部分、四周留白」，但**导出的 SVG 往往只裁到字形本身**（viewBox 恰好等于字形，如 15×15），不含那圈留白。若直接把它塞进 `size-8`（32px）的 `<img>`，字形会被放大到撑满 32px，显得又粗又大（像"图标坏了"）。做法：**保留外框做占位/对齐槽，字形按设计稿实际尺寸缩小**——
  ```html
  <!-- 设计稿：32px 外框内字形约 16px（四周有留白）-->
  <span class="flex size-8 items-center justify-center">
    <img src="/icon.svg" alt="" class="size-4" />
  </span>
  ```
  核对方法：看 Figma 里图标 Vector 的 `inset`（如 `inset-[26%]` 表示字形只占 ~48%），或比对「字形 viewBox 尺寸 ÷ 外框尺寸」，别让渲染尺寸等于整个外框。
- **方向性图标可能自带旋转——用前核对设计稿的 `rotate`**：箭头、chevron 等，Figma 常用「一枚基础斜向箭头 + `rotate-45`/`rotate-180`」组合出上下左右四个方向。**导出的素材是未旋转的基础形**，直接拿来用会指错方向（典型：轮播「上一张/下一张」渲染成斜箭头 ↙/↗ 而非 ←/→）。做法：用前在设计稿确认该实例的旋转角，再在代码补 `rotate-*`。

## 6.3 Logo 条 / 跑马灯：外框与字形都要按断点缩小

> 高频事故：Partner logo 跑马灯桌面卡是固定盒（如 232×96）。移动端只缩了 `gap`，卡片仍接近 `h-20` / `min-w-[140px]`、内部 logo 仍接近桌面宽，整条显得「还是网站端尺寸、太大了」。

- **卡片外框与内部字形必须分别做移动尺寸**，再用 `lg:`（或稿面断点）锁回桌面稿：
  - 外框示例：手机 `h-14 w-[128px]` → 平板 `md:h-20 md:w-[180px]` → 桌面 `lg:h-24 lg:w-[232px]`（数值以稿为准）。
  - 字形示例：手机约桌面的 55–70%（如 `h-5 w-[82px] lg:h-[38px] lg:w-[148px]`），禁止手机直接用桌面 `h-8 w-[148px]`。
- **禁止**移动端沿用桌面的 `min-w-[232px]` / `h-24` 一类定宽高；`min-w` 在跑马灯里尤其容易把手机卡撑得过大。
- 行间距、卡片间距同步收紧：`gap-2 md:gap-3 lg:gap-4`；区块 `py` 也按第 4 节收紧。
- 自检：在 **375** 下量一张 logo 卡的宽高，应明显小于桌面卡（常见约一半量级），且单行能露出 ≥2 张完整卡，避免「一张卡占半屏」。

## 6.4 导出素材：整段合成图 ≠ 单栏插画

> 高频事故：从 Figma/MCP 下到的 `audience.png` 实际是**整 section 截图**（左文案蓝底 + 右插画）。再塞进右栏 → 左右内容重复、比例被压扁（如 1920×900 合成图当 1:1 插画用）。

- 用图前先看素材宽高比与画面内容：若已包含标题/列表/按钮等 UI 文案，多半是**整段合成**，不能当「纯插画」用。
- **正确做法**：
  1. 按设计节点导出**仅插画/仅媒体**那一层（或对该节点 `get_screenshot`）；或
  2. 从合成图**裁切**出插画区域（如只取右半），并核对裁后比例与稿面插画框一致。
- 与「文字烤进图片」（第 6 节）配合：左栏用 HTML 实时文案，右栏只用无文案插画；禁止把整段合成图再渲染一遍当装饰。
- 自检：右栏图里是否还能读到与左栏相同的标题/列表——能读到就说明用错合成图了。

## 6.5 多层品牌标（多片 SVG 拼 logo）

> 高频事故：导出文件名是 `logo-x` / `logo-o1`…，实际 `logo-x` 是 OO、花瓣在 `o2`/`o3`。按文件名顺序横排 → 变成「OOM + 斜杠」，不像品牌标。

- 品牌标常由**叠放的多片 SVG**组成（彩色 X 花瓣叠在一起 + OO + M），不是简单从左到右各一张。
- **对照设计稿/截图**确认：哪几片要 `absolute` 叠在同一槽位、从左到右真实阅读顺序是什么；不要按文件名猜测。
- 叠放片放进同一 `relative` 容器，各片 `absolute inset-0`；字母片再按阅读顺序排列。
- 自检：375 与桌面下 logo 都应读作正确品牌名（如 XOOM），而不是「字母 + 装饰残片」。

## 7. 按钮与触控目标

- 最小触控区 **44×44px**：按钮加 `min-h-11`（44px）与足够的 `px-`。
- **按钮宽度不要一律全宽**：
  - 表单提交、页面级主 CTA（如「立即注册」「提交」）→ 手机可全宽 `w-full md:w-auto`。
  - **行内/次级操作按钮**（如「查看更多」「播放视频」「联系我们」这类短标签、带 icon 的操作）→ 保持**自适应宽度靠左**，别撑满整行。
  - 有设计稿时以稿为准；无稿时按上面「主 CTA 全宽、次级自适应」的默认判断，不要把每个按钮都写成 `w-full`。
- 并排按钮组在手机竖排：`flex flex-col gap-3 md:flex-row`。
- 可点击元素之间保持 `≥ 8px` 间距，避免误触。
- 表单输入框字号 `≥ 16px`（`text-base`），避免 iOS 自动放大。

## 7.1 行内元素在 flex 列里会被拉满宽（高频陷阱）

- `inline-flex`/`inline-block` 的**标签胶囊（pill/badge/tag）、自适应按钮**，一旦作为 `flex flex-col` 容器的直接子元素，会被默认的 `align-items: stretch` **拉伸成整行满宽**（例如把本该 100px 的小标签撑到 358px）。
- **修复**：给这些元素加 `w-fit`（或 `self-start`），强制按内容收缩、靠左：
  ```html
  <div class="flex flex-col gap-4">
    <span class="inline-flex w-fit self-start rounded-full px-3 py-1.5 ...">标签</span>
    <h2 ...>标题</h2>
  </div>
  ```
- 自检时**量一下这些元素的实际渲染宽度**：若等于容器宽度、但视觉上应是短胶囊/窄按钮，基本就是被 stretch 拉满了。

## 8. 导航（移动端汉堡菜单）

- **移动端导航使用汉堡 icon，点击展开菜单**，与网站端横向导航样式不一致是预期行为——桌面保留原横向导航，移动端切换为汉堡。
- 实现：桌面链接 `hidden md:flex`，汉堡按钮 `md:hidden`，点击后展开抽屉/全屏菜单。
- 汉堡/关闭按钮触控区 `≥ 44px`；抽屉内链接每项 `≥ 44px` 高。
- 主 CTA 可考虑常驻（sticky）或放入移动端菜单顶部。
- 多级菜单在移动端改为可展开的折叠列表（accordion），不要 hover 展开。

## 9. 公共组件一致性

- 导航、页脚等公共组件在**每一页都使用同一个组件**（同一份代码/同一套样式），不要逐页复制出不同版本。
- 修改公共组件的移动端适配时只改一处，全站生效，避免各页导航/页脚适配标准不一致。
- 若当前站点各页有重复的导航/页脚代码，应先抽成共享组件再适配。

## 10. 内容顺序与优先级

- 移动端按重要性重排：核心信息与主 CTA 上移。
- 用 `order-*`（flex/grid）调整视觉顺序而不改 DOM 语义顺序时要谨慎，优先直接调整结构。
- 桌面的「图左文右」两栏，手机通常「文字在上、图在下」或反之，按信息优先级决定。
- **移动端内容 ≠ 桌面内容的原样重排**：桌面因空间紧张（如窄卡片、多列）而**省略/截断**的正文，在手机竖向空间充足时**应补全展示**，不要照抄桌面的「仅标题」。
- **按断点区分显隐要用 CSS，不要删 DOM**：同一块内容在不同断点显示不同版本时，用 `lg:hidden` / `hidden lg:block` 控制可见性（两份都保留在 DOM 里），而不是二选一地删掉——这样能**同时满足移动与桌面**，也不破坏桌面既有表现。

## 10.1 桌面「半展开双态」→ 移动端交互形态

> 典型：桌面左栏 Advertiser 展开（标题+要点+CTA），下方仅一行变淡的 Publisher 标题；手机若照搬会又长又难切，若加了 tab 却只改标题、要点不变，等于没切换。

- **先认清桌面交互模型**：是 accordion、是上下堆叠的「当前态 + 另一态标题」、还是真正的左右分栏。
- **手机**：改为 **tab / 分段器**（或等价切换），点击后必须切换**标题 + 要点列表 +（如有）插画/logo**，不能只改标题文案。
- **桌面**：保持稿面形态（展开块 + 下方可点的另一态标题等）；**不要**把手机专用 tab 也画在桌面上（用 `lg:hidden` 藏手机 tab，桌面用稿面切换）。
- 两态内容都留在数据/DOM 里，用状态切换渲染；自检：切到 B 态后要点文案确实变成 B 的内容。

## 11. 溢出与裁切审查（步骤 5 重点）

逐项排查并修复：

- **横向溢出**：`overflow-x-hidden` 只作兜底，先找真正撑宽的元素（固定 `w-[...px]`、负 margin、超长英文/URL）。长文本加 `break-words` / `truncate`。
- **固定宽度**：把 `w-[600px]` 之类改成 `w-full max-w-[600px]`。
- **图片塌陷 / 撑爆**：确认设了固定高度/铺满的图片（`h-*`、`h-full`、`size-full`）实际渲染尺寸正确，未被全局 `img{height:auto}` 击穿（见 6.1）；非方形图标未被 `w-auto` 撑到默认 ~300px（见 6.2）。**光看整页缩略图看不出来，需按下节方法量实际渲染宽高。**
- **图片变形**：确认图片保持原比例（`h-auto`），未被拉伸或裁切。
- **内容拥挤**：间距/字号是否达到本规范下限，必要时增大 `gap`/`py`。
- **交互不适配**：hover 菜单/tooltip 在触摸端要有点击替代；轮播/拖拽要支持触摸。
- **轮播 / 跑马灯 / 分页箭头不能是「样子货」**：设计稿上的上一张/下一张、圆点，若在页面上可见且长得像按钮，就必须绑定 `scrollBy` / 切 index / 驱动 marquee 暂停后手动滚等真实行为；禁止摆两枚不会动的装饰箭头。手机端用触控滑动或同样可点的箭头（≥44px）。
- **视口配置**：确保存在 `<meta name="viewport" content="width=device-width, initial-scale=1">`。
- **粘性/固定元素**：`fixed`/`sticky` 头尾在手机不遮挡内容，注意 `safe-area`（`pb-[env(safe-area-inset-bottom)]`）。
- **1440 桌面抽检**（配合 5.1）：对含 `absolute` 大图 + 定宽文案的区块，在 1440 确认无重叠裁字。

## 12. 验证方法（不要只靠整页缩略图）

整页缩略图会把"图片塌陷/撑爆、区块巨大空档"缩得看不出来。若有可运行环境（如本地 dev server + Playwright），务必做两件事：

1. **分段截图**：把页面按约一屏高（如 900px）逐段截图审查，而不是只截一张整页缩略图。
2. **量实际渲染尺寸**：在 375px 视口下用脚本读取关键元素/图片的 `getBoundingClientRect()`，与预期比对，并检测任何 `width > 视口宽` 的元素。这是定位"图片被全局规则击穿/撑爆"这类隐形 bug 的关键——凭肉眼看截图往往漏掉。

```js
// Playwright：375px 下量图片渲染尺寸 + 找溢出元素
const imgs = await page.evaluate(() =>
  [...document.querySelectorAll('img')].map(im => {
    const r = im.getBoundingClientRect()
    return { src: im.currentSrc.split('/').pop(), w: Math.round(r.width), h: Math.round(r.height) }
  }))
const overflow = await page.evaluate(() => {
  const vw = document.documentElement.clientWidth
  return [...document.querySelectorAll('*')]
    .filter(el => el.getBoundingClientRect().width > vw + 1)
    .map(el => el.tagName + '.' + el.className).slice(0, 20)
})
// 断言：Hero 背景 h≈视口高、图标 h≈其设定值(如48)、overflow 为空
```

预期示例：铺满型背景图高度应 ≈ 视口高（非几百 → 塌陷）；图标高度应 ≈ 设定值（`h-12`→48，非 300+ → 被 `w-auto` 撑爆）。
